## [2026-10-20] Assistant
Explained this is the classic optimistic-update vs. server-truth tradeoff and started by inspecting the money model to see which options were even possible. Found the DTO already separates `available` / `pending` / `claiming` per asset (`src/shared/api/types.ts`), and `totalAvailableUsd` counts only `available`. Before finalizing a recommendation the user pivoted to the full implementation task below; the chosen approach ended up embodying the "server truth, no optimistic rewrite" answer: do not optimistically mutate the balance, instead invalidate balances on submit so the UI reflects the backend's authoritative `available`/`pending` split, show an explicit "Settling…" tracker so the user knows it worked (fixes complaint #1), and never show a value that later reverts (fixes complaint #2). Idempotency-Key guards against the double-submit in complaint #1.
